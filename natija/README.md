# بوابة الشهادة الثانوية — الولاية الشمالية 2026

مجلد `natija/` هو **الموقع كاملاً وجاهزاً للرفع كما هو**. ارفعه إلى Netlify فيصبح
محتواه هو جذر الموقع: `index.html` هي الصفحة الأولى.

## الصفحات

| الصفحة | الوظيفة |
|---|---|
| `index.html` | الصفحة الأولى — خياران: النتيجة برقم الجلوس، أو البحث عن الكليات |
| `result.html` | القسم الأول: الاستعلام عن النتيجة، وفيه زر ينقل الطالب إلى الكليات بنسبته جاهزة |
| `colleges.html` | القسم الثاني: مطابقة الكليات حسب النسبة والتخصص |
| `data/students.json` | كشف النتائج (20,681 طالباً وطالبة، 243 مدرسة) |
| `data/colleges.json` | بيانات الكليات ونِسب القبول |
| `shared/` | نظام التصميم — نسخة مزامَنة من `shared/` في جذر المستودع |

> عدّل التصميم في `shared/` بجذر المستودع ثم شغّل `bash tools/sync-shared.sh`
> حتى تنتقل التعديلات إلى `natija/shared/`.

## تحديث كشف النتائج

```bash
python3 tools/build-students.py كشف-النتائج.xlsx natija/data/students.json
```

أعمدة الكشف: الولاية، المدرسة، رقم الجلوس، الاسم (أربعة أعمدة)، ثم 18 عمود مواد،
ثم عمود النوع (1 طالبة / 2 طالب)، النسبة، والحالة.

3,223 تخصصاً في 57 جامعة وولاية، موزّعة على سبعة أقسام:

| القسم | التخصصات |
|---|---|
| السودانية – بكالريوس | 1,266 |
| السودانية – ولائي | 741 |
| السعودية | 1,103 |
| الإمارات · عُمان · بقية الدول · الشهادات الأجنبية | 113 |

### إعادة التوليد

```bash
python3 tools/build-qabool.py natijat-alqabool-2024.html natija/data/colleges.json
```

الأداة تقرأ مصفوفة `DATA` من صفحة نتيجة القبول مباشرة. ولإدخال جدول من ملف
CSV أو Excel بدلاً من ذلك:

```bash
python3 tools/build-colleges.py دليل-القبول.csv natija/data/colleges.json \
    --source "دليل القبول للجامعات السودانية 2025" --year 2025
```

### التخصصات المؤهِّلة

ملف نتيجة القبول يحمل اسم التخصص ونسبة القبول ودرجة المفاضلة فقط، ولا يحمل
المواد المؤهِّلة لكل كلية. لذلك يستنتجها `tools/classify.py` من اسم البرنامج
بقواعد مرتّبة (الطب والصيدلة والمختبرات ← أحياء، الهندسة ← هندسية، وهكذا)،
وتغطّي القواعد 3,223 برنامجاً بلا استثناء. البرامج التي لم تطابق قاعدة معروفة
تُعلَّم بـ `g:0` وتظهر في الموقع بوسم «التخصص غير مؤكد».

يظهر في الصفحة تنبيه دائم بأن التخصصات مستنتجة وأن المرجع هو شروط الكلية
في الدليل الرسمي.

### ما ليس في الملف

لا يحتوي ملف نتيجة القبول على تصنيف حكومية/أهلية ولا على المصاريف الدراسية،
فلا يوجد في الموقع فلترة بنوع الجامعة ولا بسقف المصاريف. تُضاف الحقول
`sector` و`fees` إلى سجلات `colleges` متى توفّرت بياناتها.

## نسبة المفاضلة

القبول الجامعي لا يُحسب على النسبة العامة لكل المواد، بل على **نسبة المفاضلة**
المأخوذة من أربع مواد فقط حسب قاعدة دليل القبول:

| المجموعة | المواد |
|---|---|
| العلمية | الرياضيات المتخصصة + الفيزياء + الكيمياء + أفضل مادة من (الأحياء، العلوم الهندسية، علوم الحاسوب) |
| الأدبية | اللغة العربية + اللغة الإنجليزية + الرياضيات الأساسية + أفضل مادة مؤهلة |

المواد المؤهلة في المجموعة الأدبية: الدراسات الإسلامية، التاريخ، الجغرافيا،
الأدب الإنجليزي، الفنون والتصميم.

صفحة النتيجة تحسبها وتعرضها بجانب النسبة العامة، وتمرّرها إلى صفحة الكليات.
إن تعذّر حسابها (مادة ناقصة أو درجة غير رقمية) يرجع الموقع إلى النسبة العامة.
القاعدة معرّفة في `js/tracks.js` تحت `MUFADALA`.

## قاعدة الترميز اللوني

الفارق = نسبة قبول الكلية − نسبة الطالب:

| الفارق | اللون | الحكم | الترتيب |
|---|---|---|---|
| 10 فأكثر | أحمر | ضعيف أو معدوم | آخر القائمة |
| أكبر من صفر وأقل من 10 | برتقالي | قبول محتمل | أعلى القائمة |
| من −5 إلى صفر | أخضر خفيف | قبول | بعد البرتقالي |
| أقل من −5 | أخضر غامق | قبول مرتفع | بعد الأخضر الخفيف |

وداخل كل مجموعة تُرتَّب الكليات بالأقرب إلى نسبة الطالب أولاً.
الحدود معرّفة في أول `js/colleges.js` تحت `RULES`، وتعديلها يتم من مكان واحد.

## عدّاد الزيارات

العدّاد صار جزءاً من الموقع نفسه، في `netlify/functions/visits.js`، بلا أي حزم
خارجية ولا `npm install`. يُرفع مع المجلد فيعمل تلقائياً.

| الملف | الوظيفة |
|---|---|
| `netlify/functions/visits.js` | الدالة: تعدّ الزيارات والمتصلين والدول |
| `netlify.toml` | توجيه `/api/visits` إلى الدالة |
| `check.html` | صفحة فحص تخبرك بحالة العدّاد وسبب أي خلل |

الدالة مكتوبة بصيغة `exports.handler` الكلاسيكية وهي أوسع الصيغ توافقاً،
تعمل مع الرفع اليدوي ومع الربط بمستودع، وبلا أي حزمة خارجية.

### كيف يعمل

يطلب الموقع `‎/api/visits?m=hit|ping&sid=<معرّف الجلسة>‎` فيردّ:

```json
{ "ok": true, "total": 48213, "online": 3,
  "countries": [ { "code": "SD", "n": 31000 }, { "code": "SA", "n": 9100 } ] }
```

- **الإجمالي**: يزيد مرة واحدة لكل جلسة زيارة، مهما تنقّل الزائر بين الصفحات
  الثلاث. الحماية مزدوجة: المتصفح يرسل `hit` مرة واحدة فقط، والدالة نفسها
  لا تحتسب معرّف جلسة سبق أن رأته.
- **المتصلون الآن**: عدد الجلسات النشطة خلال آخر خمس دقائق.
- **الدول**: تُقرأ من بيانات Netlify الجغرافية، ويحوّلها الموقع إلى علم واسم عربي.
- **التخزين**: Netlify Blobs، وهو مستقل عن ملفات الموقع، فالأرقام **لا تتصفّر
  عند رفع نسخة جديدة**.

### الاستمرار من الأرقام الحالية — خطوة واحدة مهمة

المخزن الجديد يبدأ فارغاً، فلا بد من إخباره بآخر رقم ظاهر في الموقع الحالي
**قبل** الرفع، وإلا بدأ من الصفر. افتح `netlify/functions/visits.js` وعدّل
أول سطرين:

```js
const SEED = {
  total: 48210,                                   // آخر إجمالي زيارات ظاهر
  countries: { SD: 31000, SA: 9100, EG: 3200 }    // آخر توزيع للدول
};
```

أو اضبطهما من إعدادات Netlify كمتغيّري بيئة بدل تعديل الملف:

```
VISITS_SEED_TOTAL = 48210
VISITS_SEED_COUNTRIES = {"SD":31000,"SA":9100,"EG":3200}
```

هذه القيم تُستخدم **مرة واحدة فقط** عند أول تشغيل والمخزن فارغ. بعدها يقرأ
العدّاد من المخزن دائماً، ولو رفعت الموقع مئة مرة ولو بقيت البذرة صفراً.

### إن كان لديك عدّاد يعمل الآن

الدالة الجديدة تستبدل المسار `‎/api/visits‎`. إن كانت لديك دالة قديمة تعمل
وتحتفظ بالأرقام، فأمامك خياران: إمّا نسخ دالتك القديمة مكان الجديدة والإبقاء
عليها كما هي، وإمّا استخدام الجديدة بعد ضبط البذرة بآخر أرقامك كما في الأعلى.
لا تجمع بين الاثنتين على نفس المسار.

### التحقق بعد الرفع

افتح `https://<موقعك>/check.html` فتخبرك الصفحة بالحالة والسبب والحل.
أو مباشرة `https://<موقعك>/api/visits?m=health`:

- `"storage":"netlify-blobs"` التخزين يعمل والأرقام محفوظة.
- `"storage":"memory-only"` مخزن Blobs غير مفعّل، فالأرقام ستضيع عند إعادة
  تشغيل الدالة — فعّله من إعدادات الموقع.
- صفحة «Page not found» تعني أن الدالة لم تُنشر أصلاً، وعلاجها في الجدول أدناه.

وإن تعذّر التخزين تماماً ترد الدالة `ok:false` فيُخفي الموقع صندوق العدّاد
بدل إظهار رقم مصفَّر مغلوط.

### إذا لم يظهر العدّاد بعد الرفع

| الحالة | السبب | الحل |
|---|---|---|
| `check.html` يقول «الدالة غير منشورة» | طريقة الرفع لم تنشر الدوال | اربط الموقع بمستودع GitHub واجعل مجلد النشر `natija`، أو تأكد من رفع `netlify.toml` ومجلد `netlify/functions` مع الموقع |
| `/api/visits` يعطي 404 والدالة تعمل | توجيه `netlify.toml` لم يُقرأ | لا حاجة لشيء: الموقع يجرّب `/.netlify/functions/visits` تلقائياً ويتذكّر المسار الناجح |
| يعمل لكن الرقم صغير | البذرة لم تُضبط قبل أول تشغيل | اضبط `SEED` أو متغيّرات البيئة، ثم احذف مدخل `visits/state` من Blobs ليُعاد التهيئة |

عند الربط بمستودع GitHub يوجد في جذر المستودع `netlify.toml` جاهز يضبط
مجلد النشر `natija` ومجلد الدوال `natija/netlify/functions`.

```bash
python3 -m http.server 8000
# ثم افتح http://localhost:8000/natija/
```

## المصادر وما ينقص

قاعدة حساب نسبة المفاضلة والمواد المؤهلة مأخوذة من قواعد دليل القبول المنشورة
من الإدارة العامة للقبول وتوثيق الشهادات بوزارة التعليم العالي.

نِسب القبول ودرجات المفاضلة مأخوذة كما هي من ملف نتيجة القبول 2024 بلا تعديل
في الأرقام. **ما زال ناقصاً:** تصنيف الجامعات حكومية/أهلية، والمصاريف الدراسية،
والمواد المؤهِّلة الرسمية لكل كلية.
